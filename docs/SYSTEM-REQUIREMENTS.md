# Системные требования

Обновлено: 26 октября 2026. Приложение 1.0.1; Avalonia-порт 12.1.4 / .NET 10, Windows WPF / .NET Framework 4.8. План расширения — [PLATFORM-ROADMAP.md](PLATFORM-ROADMAP.md), [issue #2](https://github.com/MimicBYE/AnimeTracker/issues/2).

## Как читать требования

«Техническое ограничение» подтверждено конфигурацией проекта или документацией зависимости. «Целевой минимум» и «рекомендуется» — предварительные бюджеты проекта, а не результаты нагрузочного тестирования. Измеренных минимальных RAM/CPU/диска сейчас нет. Числа ниже нельзя использовать как гарантию запуска на любом таком устройстве.

В AT-5 библиотека Avalonia переведена на виртуализированный список, ввод поиска объединяется с задержкой 250 мс. Есть [локальный замер обработчиков на 1000/5000 записях](validation/2026-10-26-search-windows.md) под Windows и автоматическая проверка viewport; это не замер FPS, памяти или нативного Mac UI. Остальные бюджеты ниже не меняются; кеш bitmap и остальные списки требуют отдельного профилирования.

Поддержка зависимости не равна поддержке Anime Tracker. Платформа получает статус проверенной только после теста готового Release-пакета на заявленной нижней границе ОС и оборудовании. Сборка на GitHub runner и общий тест Core не подтверждают весь нативный интерфейс.

Для 1.0.1 выполнена [ограниченная ручная проверка Windows 11 build 26200](validation/1.0.1-windows.md): +1, отказ записи, перезапуск, восстановление XML, фильтры и подбор. Остальные версии Windows, аппаратные минимумы, жесты виджета и нативный Mac по этому отчёту не подтверждаются.

Для следующего подтверждённого выпуска целевая нижняя граница — macOS 15; поднятие `Info.plist` и фактическая проверка должны идти отдельным изменением. Существующий архив 1.0 этим документом не меняется. [Поддерживаемые ОС .NET 10](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md).

Windows 10 — прежняя граница совместимости проекта, не обещание поддержки всех редакций ОС её изготовителем. Для новых установок рекомендуем поддерживаемую Windows 11. Политика исправлений приложения — [SECURITY.md](../SECURITY.md); перед выпуском проверять lifecycle выбранных ОС и зависимостей.

## Предварительные бюджеты desktop

Это ресурсы всего устройства; объём свободного диска указан для распакованного приложения и базовых данных **без** растущего кеша, резервных копий и места для обновления.

| Платформа | Целевой минимум для проверки | Рекомендуемая конфигурация |
| --- | --- | --- |
| Windows | Windows 10/11 x64 с Framework 4.8+, 2 ядра x64, 4 ГиБ RAM, 0.5 ГиБ свободно, экран 1280×800 при 100% | Поддерживаемая Windows 11, 4 ядра, 8 ГиБ RAM, 2 ГиБ плюс кеш/backup, 1920×1080 |
| macOS | Цель следующей проверки: macOS 15+, Apple M1, 8 ГиБ RAM, 1 ГиБ свободно, рабочая область от 1100×700 логических точек | macOS 26 с проверенным runtime, M1 и новее, 16 ГиБ RAM, 2 ГиБ плюс кеш/backup, рабочая область от 1440×900 |
| Linux — план | Ubuntu 24.04 LTS x64, X11/XWayland, 2 ядра, 4 ГиБ RAM, 1 ГиБ свободно, 1280×800 при 100% | Ubuntu 26.04 LTS x64, 4 ядра, 8 ГиБ RAM, 2 ГиБ плюс кеш/backup, 1920×1080; GNOME/KDE проверены отдельно перед выпуском |

Экранные бюджеты требуют проверки с декорациями окон и масштабом. Avalonia-окно сейчас имеет минимум 850×520 и начальный размер 1040×800: на небольшом экране его нужно уметь уменьшить. Разрешение физической панели не заменяет логическую рабочую область при HiDPI. WPF-версия проверяется отдельно.

### Linux: зависимости выбранного пакета

Для планируемого self-contained `linux-x64` .NET Runtime устанавливать отдельно не нужно, но остаются нативные библиотеки ОС. Базовый список Avalonia для Debian/Ubuntu: `libx11-6`, `libice6`, `libsm6`, `libfontconfig1`. Нужны также нативные зависимости .NET (например ICU/OpenSSL/zlib) из поддерживаемого дистрибутива; точные пакеты и версии зафиксировать после проверки L0 на чистой Ubuntu, а не выдавать этот список за готовую команду установки. [Зависимости Avalonia](https://docs.avaloniaui.net/docs/supported-platforms).

Базовый .NET 10 glibc ABI для x64/ARM64 — 2.27, но это не поддержка любого старого Linux с таким libc. В MVP выбирается Ubuntu 24.04/26.04; пакет должен быть собран и проверен с нативными библиотеками для этой матрицы. Alpine/musl, ARM32 и ARM64 пока исключены. [Требования .NET 10](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md).

Нужен графический сеанс. Для начального X11 backend в Wayland-сеансе требуется XWayland; нативный Wayland — отдельная опция будущего пакета. Рендеринг должен сохранять software fallback при недоступном GPU. Драйвер/GLX и software-режим тестируются отдельно; числовой GPU-минимум без замера не задан. Трей необязателен, его поддержка зависит от оболочки. [Linux](https://docs.avaloniaui.net/docs/platform-specific-guides/linux), [TrayIcon](https://docs.avaloniaui.net/controls/navigation/trayicon).

## Мобильные цели, пока без поддержки

| Платформа | Целевой минимум для прототипа | Рекомендуется для основной проверки |
| --- | --- | --- |
| Android | Android 14 / API 34, ARM64, 3 ГиБ RAM, 1 ГиБ свободно без кеша, область от 360×640 dp | Android 16 / API 36 или более новая версия после проверки выбранных зависимостей, ARM64, 6 ГиБ RAM, 2 ГиБ плюс кеш/backup |
| iOS/iPadOS | iOS/iPadOS 18, ARM64, устройство с 4 ГиБ RAM, 1 ГиБ свободно без кеша; iPhone от 375 логических точек по ширине | iOS/iPadOS 26 или более новая версия после проверки, устройство с 6 ГиБ RAM, 2 ГиБ плюс кеш/backup; отдельно iPhone и iPad |

Эти версии выбраны по пересечению матриц .NET/Avalonia на дату анализа; более низкий SDK deployment target не обещает поддержку проекта. Версии новее рекомендуемых нужно добавлять после проверки совместимых workload и UI. Runtime поставляется вместе с мобильным пакетом. Мобильные бюджеты, включая память при декодировании обложек, подлежат проверке на физическом устройстве. [Avalonia](https://docs.avaloniaui.net/docs/supported-platforms), [изменения Avalonia 12](https://docs.avaloniaui.net/docs/avalonia12-breaking-changes).

Необходимы доступ к системному выбору файлов для импорта/экспорта и HTTPS для онлайн-каталога. Постоянный процесс, системный трей и desktop-окно не требуются. Домашние виджеты — отдельные функции с ограничениями ОС, не условие работы библиотеки.

## Данные, сеть и рост диска

Библиотека, ручное редактирование и импорт локального XML/GZIP работают без сети. Поиск Shikimori, новые обложки, связи и расписание требуют доступа к внешним HTTPS-сервисам; фиксированная скорость интернета для приложения не установлена.

В `CoverSource` ответ одной обложки ограничен 8 МиБ; это предел одного скачивания, а не общий лимит кеша. Сейчас общего дискового лимита нет. Размер зависит от числа и фактического размера обложек, импортов и backup. Для планирования места использовать:

```text
свободное место = приложение + XML/импорты + кеш + backup + временная копия обновления/переноса
```

Например, 1 000 обложек по 200 КиБ занимают около 195 МиБ, а по 8 МиБ — около 7.8 ГиБ; это расчёт, не измерение реальной библиотеки. Для переноса нужно место под новую папку при сохранённой старой, для ZIP-backup — ещё под архив. Мобильный порт должен ввести очищаемый ограниченный кеш до заявления минимальных требований.

## Проверка и обновление требований

Ответственный — автор платформенного/производительного изменения; проверяющий PR сверяет этот документ и README. Пересматривать при добавлении ОС/архитектуры, изменении .NET/Avalonia/нативных зависимостей, упаковки, рендеринга, анимаций, кеша, фоновой работы или объёма данных. Перед каждым стабильным выпуском перепроверять внешние lifecycle-матрицы. Автоматической периодической задачи этим документом не создаётся.

Для каждой нижней/рекомендуемой конфигурации сохранять отчёт `docs/validation/<версия>-<платформа>.md`: commit, пакет и SHA-256, дата, ОС/DE/backend, CPU/RAM/GPU/драйвер, экран/DPI, режим питания, версия toolchain; наборы 100/1 000/5 000 синтетических записей, холодный/тёплый кеш. Фиксировать отсутствие проверки, если нужного устройства нет; общий CI не подставлять вместо отчёта устройства.

Замерять Release без debugger: три холодных/тёплых запуска (время до доступной библиотеки), пять минут покоя (CPU/RAM), минуту прокрутки, поиск и +1, импорт 1 000 записей, повторную навигацию 20 раз (рост памяти), offline/restart, пиковую память/диск, suspend/resume на телефоне. Для длинных операций показывать занятость и сохранять возможность отмены. Сеть измерять отдельно от локальной отзывчивости. На Windows — working set, Linux — RSS, Mac — footprint, mobile — инструменты платформы; показатели разных ОС напрямую не смешивать.

Предварительные цели приёмки на библиотеке 1 000 записей: тёплый старт ≤3 с, локальный +1/фильтр p95 ≤200 мс (не менее 100 действий), средний idle CPU ≤2% в пересчёте на одно логическое ядро без активного обновления. Desktop RAM в покое ≤400 МиБ, пик при прокрутке ≤750 МиБ; mobile — ≤250/450 МиБ. Это инженерные цели будущего профилирования, а не обещание текущей версии. На слабом устройстве отдельно проверить software rendering; на телефоне — расход батареи и отсутствие постоянного polling в фоне.

Если цель не выполнена: приложить измерение, устранить проблему или обоснованно изменить бюджет/минимум в том же PR. Повышение минимума отражать в release notes, README, метаданных пакета и матрице CI одновременно. В отчёте различать «собралось», «запустилось», «пройден пользовательский сценарий» и «прошли замеры».
