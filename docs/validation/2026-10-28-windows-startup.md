# AT-18 — восстановление автозапуска Windows

28 октября 2026. База dev `dccf2e4`. Windows/WPF, C# 5/.NET Framework 4.8. Личная библиотека не использовалась для тестов. Приватные резервные копии и журналы находятся вне исходников/релизных архивов.

## Наблюдение и границы диагноза

Владелец сообщил, что после входа не появляется даже значок трея. Старая HKCU Run-запись присутствовала и указывала на существующий EXE с корректным quoted `--startup`. Для Anime Tracker не найдены явные записи запрета StartupApproved, дубли Run/RunOnce/задач, политики отключения Run и относящиеся к приложению сбои в доступном Application-журнале. Обнаруженный процесс был запущен вручную, без `--startup`.

Историческая причина пропуска Run **не подтверждена**. Отсутствие ошибки в журнале не доказывает, что Windows вызывала программу. Для дальнейшей диагностики добавлен журнал этапов, а регистрация восстановлена через другой штатный механизм. Windows/Explorer не перезагружались и системные запреты не обходились.

## Изменение

- Ярлык `Anime Tracker.lnk` находится в `Environment.SpecialFolder.Startup`. TargetPath — фактический файл сборки, Arguments — `--startup`, WorkingDirectory — папка приложения. Это поддерживает переименование EXE, пробелы/Unicode и запуск из чужой рабочей папки.
- Создание/чтение выполняется через Unicode `IShellLinkW` и `IPersistFile`, без поиска перемещённого EXE. Первоначальный WScript.Shell отклонял кириллический TargetPath на Windows CI; локально воспроизведён его отказ для японского пути. От варианта WScript.Shell отказались; self-test теперь использует одновременно кириллицу, пробелы и японские символы. [Интерфейс Windows Shell](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ishelllinkw).
- Новый ярлык сначала сохраняется под временным именем и перечитывается. Замена существующего файла атомарна; старая Run-запись удаляется только после успешной проверки. При отказе записи старый запуск сохраняется. Повторное включение исправляет устаревший путь, отключение удаляет оба способа.
- Старая корректная Run-запись по-прежнему распознаётся. Повторное «Применить» с отмеченным автозапуском выполняет перенос/восстановление, даже если флажок уже был включён.
- `startup.log` в пользовательском LocalAppData содержит UTC, PID и стадии: starting startup/manual, initializing, library-loaded, tray-created, running (режим/открытие библиотеки/включение виджета), already-running или failed. Порог ротации — 64 КиБ, сохраняется одна предыдущая копия; последняя строка может пересечь порог; ошибки записи журнала не останавливают приложение. Библиотека, заметки, секреты и произвольная командная строка не логируются.
- `tray-created` означает создание NotifyIcon и запрос его показа, а не самостоятельное доказательство видимости значка. Для текущего запуска видимость отдельно подтвердил владелец.

Основание: [Startup folders и управление автозагрузкой Windows](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows), [особенности и отсутствие гарантий времени запуска Run](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).

## Выполнено

- Самопроверка на временных папках и уникальном приватном тестовом ключе HKCU (не настоящем Run): миграция legacy, COM round-trip TargetPath/Arguments/WorkingDirectory, пробелы/Unicode, повторное включение без дублей, переезд EXE, отключение, отказ записи с сохранением legacy и уборкой временного ярлыка — PASS. Тестовые ключи удаляются в finally.
- Проверка границ строк и ротации журнала — PASS. В self-test не используется настоящий startup.log.
- Windows Release package: self-test, MAL/XML/GZIP import, архивы и повторная сборка/самопроверка из извлечённых исходников — PASS. Release.Tests.ps1 — PASS.
- Отдельный реальный процесс `--startup` запущен из System32 на пустой тестовой библиотеке с отключённым виджетом. Получены `starting startup → initializing → library-loaded → tray-created → running mode=startup library-open=False widget-enabled=False` — PASS.
- После резервной копии заменены только рабочие EXE/config и перенесена регистрация; проверены поля реального ярлыка и отсутствие старого Run-дубля. Запуск этим ярлыком дал `running mode=startup library-open=False widget-enabled=True` — PASS.
- Владелец подтвердил: **«Да, виджет и значок есть»**. Повторный `--startup` завершился через already-running, без второго экземпляра и чтения библиотеки — PASS.
- SHA-256 личного library.xml до/после установки и старта совпал. Финальная сборка с IShellLinkW также установлена и запущена настоящим ярлыком: журнал подтвердил startup/tray/widget, SHA библиотеки совпал. Установленный локальный EXE: `80e7adc7f0f922e361f4b221888b83b0906af322461e98e7355778c0d7b01273`. Релизные EXE могут отличаться временем сборки; этот хеш относится к конкретной установленной сборке.
