# Подготовка единого релиза GitHub

Автоматическая схема описана в [CI.md](CI.md): `main` публикует новый стабильный номер из `VERSION`, `dev` — отдельный Pre-release. Оба канала содержат Windows, macOS и исходники вместе. Ниже — ручная подготовка папки без публикации; она остаётся доступной для локальной проверки.

Версия обеих платформ — **1.0**, тег релиза — **v1.0**. Windows и macOS публикуются в одном релизе.

Сначала соберите Mac-архив с установленным SDK .NET 10, затем подготовьте папку для публикации:

```powershell
.\scripts\build-macos.ps1
.\scripts\prepare-github.ps1
```

Скрипт подготовки собирает и проверяет Windows-архив, проверяет Mac-архив и создаёт новую папку `AnimeTracker-GitHub` рядом с проектом. Существующая папка не перезаписывается; для повторной подготовки укажите другой путь:

```powershell
.\scripts\prepare-github.ps1 -OutputDirectory ..\AnimeTracker-GitHub-next
```

## Содержимое папки

- `repository/` — исходники обеих платформ, README, тесты, скрипты и документация для репозитория.
- `releases/v1.0/` — Windows ZIP, macOS ZIP, архив исходников, общий `SHA256SUMS.txt` и описание релиза `RELEASE-NOTES.md`.
- `START_HERE.md` — краткая инструкция.
- `verification.json` — проверка состава файлов, ссылок документации и архивов.

В исходный репозиторий загружается содержимое `repository/`. Три ZIP-файла и `SHA256SUMS.txt` прикрепляются к единому релизу **Anime Tracker 1.0**. Текст описания берётся из `RELEASE-NOTES.md`.

Личная библиотека, импорты, обложки, SDK, кеши и промежуточные сборки не копируются. Скрипт не отправляет коммиты и не публикует релиз автоматически. Подготовленные номера версий берутся из `VERSION`; проект macOS должен иметь такую же версию.

Лицензия собственного кода пока не выбрана. Атрибуция и лицензии сторонних компонентов сохранены. Ограничения платформ и инструкции по запуску приведены в README и инструкции macOS.
