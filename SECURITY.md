# Безопасность

## Поддерживаемые версии

Исправления безопасности выпускаются для последней стабильной версии Anime Tracker. Старые архивы доступны для истории; отдельного сопровождения каждой старой версии нет. Сборки `dev` предназначены для проверки изменений и не заменяют стабильный релиз.

## Сообщить об уязвимости

Используйте [приватное сообщение через GitHub Security Advisories](https://github.com/MimicBYE/AnimeTracker/security/advisories/new), раздел **Security → Report a vulnerability**. Приватные сообщения включены для репозитория.

Укажите версию, ОС, затронутую функцию, ожидаемый и фактический результат, минимальные шаги воспроизведения и возможные последствия. Пример файла должен быть искусственным или обезличенным. Не прикладывайте свою библиотеку, импорты MAL, резервные копии, токены или личные данные.

До согласованного раскрытия не публикуйте действующие exploit-примеры и детали уязвимости в обычном issue. Если приватная форма недоступна, откройте issue только с просьбой указать безопасный канал связи, без деталей эксплуатации. Фиксированного срока ответа и программы вознаграждений нет.

## Требования к изменениям

- Данные каталогов, обложки и импортированные файлы считаются внешними данными. Они не должны выполнять команды или изменять настройки доступа. XML-импорт запрещает DTD и внешние сущности; пути и размеры загружаемых файлов проверяются.
- Личная библиотека хранится локально. Статусы, серии, оценки, заметки и ID сохраняются при миграции и обновлении метаданных. Проверки используют отдельные тестовые данные; настоящая `data` не попадает в Git, отчёты CI и релизные архивы.
- Не храните PAT, пароли, сертификаты подписи или другие секреты в коде, конфигурации, issue и логах. Необходимые секреты передаются окружением только нужной задаче.
- Проверки PR выполняются с правами чтения. Право `contents: write` получает только публикация после успешного CI; код PR не запускается через `pull_request_target` с токеном записи.
- Actions закрепляются полными SHA. Теги и вложения опубликованного релиза не перезаписываются; перед публикацией проверяются происхождение пакетов и SHA-256.
- Приложение не требует запуска от администратора. Не добавляйте команды отключения системной защиты, Gatekeeper или проверки TLS в пользовательские инструкции.

## Зависимости

Используются три уровня проверки:

1. **NuGet Audit при restore:** прямые и транзитивные пакеты; High/Critical, ошибки получения базы и отсутствие поддерживаемого audit source останавливают restore.
2. **Полный аудит в CI и еженедельно:** `scripts/check-dependencies.ps1` проверяет все SDK-проекты, включая транзитивные зависимости. High/Critical блокируют CI и публикацию. Low/Moderate сохраняются в отчёте и требуют оценки; неизвестный или неполный формат отчёта не считается успешной проверкой.
3. **Dependency Review для PR:** запрещает добавление зависимостей с известными High/Critical во всех scopes, включая GitHub Actions. Dependabot еженедельно предлагает обновления NuGet и Actions; alerts и security updates включены. Автоматического merge нет.

Обычные Dependabot PR направляются в `dev`. Security updates GitHub могут направляться в основную ветку; они также требуют review и CI. Проверки кода и пакетов не гарантируют отсутствия всех уязвимостей. Системный .NET Framework Windows обновляется средствами Windows и не охватывается NuGet-сканированием. Обновление SDK из `global.json` проверяется отдельно.

Не отключайте аудит и не добавляйте исключения advisories ради зелёного CI. Исключение возможно только с обоснованием риска и принятым владельцем review; исправление зависимости предпочтительнее подавления.

Подпись издателя Windows (Authenticode), Apple Developer ID и нотарификация Mac не настроены. Локальная ad-hoc подпись Mac и SHA-256 подтверждают целостность проверяемых файлов, но не заменяют доверенную подпись издателя.
